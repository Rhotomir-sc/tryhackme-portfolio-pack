# Lab documentation standard

Start with the question, environment, key finding, evidence references, and limitation. Keep technical results distinct from assumptions and platform-provided conclusions.

For a new or revisited lab, record:
- Execution date and timezone; room/scenario and tool versions.
- Input source and whether it may be redistributed. Use a source reference when raw training data cannot be shared.
- Exact relevant commands or queries, with meaningful output excerpts.
- A finding-to-evidence mapping, alternative explanation, and follow-up.
- What was changed and how the change was verified, where applicable.

Do not invent missing dates, outputs, or personal reflections. Completion screens are not substitutes for technical evidence.
